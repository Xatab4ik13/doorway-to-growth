SEO-подготовка пяти доменов Brandoors (бренд межкомнатных и входных дверей, 5 партнёрских сайтов на собственных TLD).

Предпосылки (проверено по состоянию на сейчас)
- SEO-сканер Lovable ни разу не запускался — все 6 сканеров в статусе `not_scanned`.
- Semrush (RU-база) видит только `brandoors.su` (1 ключевое слово «двери барроуз» на позиции 90, трафик ≈ 0). Остальные 4 домена ещё не проиндексированы/не имеют видимости.
- Уже сделано: Яндекс.Метрика счётчики настроены, домены привязаны к Яндекс.Вебмастеру.
- Ограничения проекта: без блога, без wildcard-поддоменов, локальное SEO, мультитенантный SPA (один билд на 5 TLD), динамические мета-теги через `sites.domain`.

Цель плана
Подготовить все 5 доменов к SEO-продвижению: технически привести их в порядок, настроить индексацию, локальные сигналы, контентные страницы и аналитику, чтобы поисковики могли ранжировать каждый сайт как самостоятельный торговый представитель Brandoors.

Фаза 1. Технический аудит и базовые исправления

1. Запустить SEO-скан Lovable
   - Запустить `seo_chat--trigger_scan` для получения текущего списка ошибок (title, description, canonical, robots, sitemap, lighthouse, метаданные, HTTP-заголовки).
   - Дождаться результатов и разобрать каждое `failing` finding.

2. Head-метаданные
   - Заменить в `index.html` шаблонные `Lovable App` / `Lovable Generated Project` на брендовые значения по умолчанию.
   - Включить sitewide JSON-LD `Organization` / `WebSite` для Brandoors.
   - Проверить/добавить `viewport`, `charset`, `twitter:card`.
   - `og:type` — `website` для главных страниц; `og:image` — только если будет готов абсолютный URL общего превью.

3. robots.txt и sitemap.xml
   - Создать или обновить `public/robots.txt` с `User-agent: *` `Allow: /` и путём к sitemap.
   - Создать/обновить `public/sitemap.xml` (или `scripts/generate-sitemap.ts` + `prebuild`/`predev`), включив все публичные маршруты каждого домена и динамические URL (каталог, страницы коллекций, товары, контакты, о бренде, шоурумы).
   - Убедиться, что в sitemap не попадают внутренние/админ-роуты (`/login`, `/partner`, `/crm`, `/admin`, `/not-found`).

4. Canonical и самоканонизация
   - Для каждого домена canonical должен указывать на свой собственный TLD (не на `brandoors.su` или preview URL).
   - Реализовать через `react-helmet-async` или динамическую подстановку `window.location.origin` на стороне клиента + статичный fallback в `index.html`.
   - Устранить дублирование страниц каталога с разными параметрами фильтров — canonical всегда на «чистый» URL, либо `noindex` для глубоких фильтров.

5. JSON-LD и Schema.org
   - Добавить `Organization` schema с адресом, телефоном, ссылками на 5 доменов (sameAs).
   - `LocalBusiness` / `Store` для каждого шоурума (адрес, телефон, часы работы, геокоординаты).
   - `Product` schema для карточек товаров (название, описание, изображение, цену/цену «по запросу», бренд, availability).
   - `BreadcrumbList` для страниц каталога и товара.

Фаза 2. Яндекс-специфическая оптимизация

6. Яндекс.Вебмастер: проверка и отправка
   - Для каждого домена подтвердить право собственности в Вебмастере (уже привязано — проверить статус).
   - Отправить `sitemap.xml` для каждого из 5 доменов отдельно.
   - Проверить «История URL» и региональность каждого сайта.

7. Вебвизор (запись сессий)
   - Включить `webvisor: true` в коде инициализации Метрики для всех 5 счётчиков.
   - При необходимости включить `accurateTrackBounce` и `trackLinks`.
   - Проверить в личном кабинете Метрики, что для каждого счётчика включён «Вебвизор».

8. Региональность
   - В Вебмастере для каждого домена указать соответствующий регион (Москва/МО / Другие регионы по фактическим адресам шоурумов).

9. Турбо-страницы / RSS (опционально, по желанию)
   - Если важна скорость индексации в Яндексе — настроить RSS-канал для товаров/коллекций и добавить в Вебмастер.

10. Файл robots для Яндекса

    - Для динамических фильтров каталога (по цвету, остеклению и т.д.) решить: либо `noindex` + canonical, либо ограничить crawl.

Фаза 4. Контент и структура

16. Страницы коллекций как SEO-заходы
    - ESTETICA, GHOST, HEAVY, PRIME, REFLECT, MAZE — каждая коллекция должна иметь свою страницу с:
      - уникальным H1 и title;
      - текстовым описанием (2–4 абзаца: материалы, стиль, философия);
      - галереей рендеров/фото;
      - ссылкой в каталог с предустановленным фильтром.

17. Каталог: SEO-правильные URL и фильтры
    - URL товара: `/catalog/:slug` или `/product/:slug` — короткие, человекочитаемые.
    - URL категории: `/catalog?category=...&collection=...` — параметризованные, но с canonical на чистый вариант.
    - Заголовки товарных страниц: `[Модель] — [Коллекция] — двери Brandoors [Москва/Салон]`.
    - Мета-описания: уникальные для каждого товара, не шаблонные.

18. Главная страница
    - Уникальный title/description для каждого домена.
    - Структура: H1 → блоки коллекций → преимущества → CTA → контакты.
    - «Doors Collections» на главной уже ведёт в каталог с фильтрами — проверить, что фильтры применяются корректно.

19. О бренде / шоурум / технологии
    - Добавить/проверить страницы:
      - `/about` / `/brand` — официальная презентация (PDF в прошлом была основой);
      - `/showroom` — видео-тур, карта, фото интерьера;
      - `/tech` / `/materials` — технические характеристики, материалы, покрытия.
    - Все эти страницы — с JSON-LD и уникальными мета-тегами.

20. Изображения
    - Проверить alt-теги для всех фото товаров и коллекций.
    - Подтвердить, что все изображения WebP, ≤ 800 px по высоте, lazy loading.
    - Для фото в каталоге реализовать srcset для Retina/мобильных.

20a. Внутренняя перелинковка (A ↔ B ↔ C)
    - Схема «хаб-и-спицы»: категорийные страницы каталога (A) — главные хабы, страницы салонов (B) и коллекций (C) — спицы.
    - С каждой страницы коллекции (C) — ссылка в соответствующую категорию каталога (A) и на ближайший салон (B).
    - Со страницы салона (B) — ссылки на топ-категории (A) и 2–3 коллекции (C) с описательными анкорами («двери скрытого монтажа GHOST»).
    - С категорийных страниц (A) — блок «Коллекции в этой категории» (C) и «Посмотреть вживую в салоне» (B).
    - Хлебные крошки `BreadcrumbList` на всех страницах A/B/C — единая иерархия для веса и сниппетов.
    - Правило: любая важная страница — не глубже 3 кликов от главной; анкоры описательные, без «здесь»/«подробнее».
    - Перелинковка только внутри своего домена — никаких кросс-доменных ссылок между 5 TLD (иначе Яндекс склеит их как аффилиаты).

Фаза 5. Мультидоменная стратегия и избежание дублирования

21. Уникальность контента между доменами
    - Не допустить 100% идентичных title/description/H1 на разных TLD.
    - Разделить акценты: кто-то — «склад», кто-то — «шоурум», кто-то — «декоратор», кто-то — «квартирный ремонт».

22. canonical на собственный домен
    - Каждая страница каждого сайта должна canonical-изироваться на `https://<свой-domain>/<path>`.
    - Исключить перекрёстные canonical между доменами (например, `brandoors.moscow` не должен canonical на `brandoors.su`).

23. hreflang (не нужен)
    - Для 5 русскоязычных доменов без языковых версий hreflang не используем. Если в будущем появится английская версия — добавить.

24. Редиректы и www
    - Настроить на уровне nginx/Timeweb: либо www → non-www, либо наоборот, единообразно для всех 5 доменов.
    - HTTP → HTTPS редирект обязателен.
    - В sitemap и canonical использовать основной (предпочтительный) вариант.

7. Уникализировать главные страницы и мета-теги для каждого домена.

После запуска
12. Регулярный мониторинг позиций, индексации, целей и перезапуск SEO-сканов.

Ожидаемый результат
- Все 5 доменов технически готовы к индексации.
- Уникальные мета-данные и структура для каждого домена.
- Корректная работа Вебвизора и целей Метрики.
