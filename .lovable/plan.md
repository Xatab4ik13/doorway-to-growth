# SEO: анализ за месяц и план исправлений

## Что показал Яндекс.Вебмастер (данные по API, 26.07–23.08)

| Домен | Страниц в поиске | Показов | Кликов | ИКС |
|---|---|---|---|---|
| brandoors.moscow | 1 | ~31 | 1 | 0 |
| brandoors.online | 3 | ~20 | 7 | 0 |
| brandoors.pro | 2 | ~21 | 1 | 0 |
| brandoors.store | 4 | мало | 0 | 0 |
| brandoors.su | 1 | ~4 | 0 | 0 |

Sitemap загружены на всех доменах (23 URL каждый, ошибок нет), робот заходит регулярно. Но в поиск попадает 1–4 страницы из 23. Все запросы — только брендовые («brandoors», «brandoors двери»), коммерческих («входные двери купить москва» и т.п.) нет вообще.

## Главная причина (найдена)

Сайт — SPA без серверного рендеринга. Любой URL отдаёт роботу **одинаковый пустой HTML**: одинаковый `<title>`, одинаковый description и `canonical="/"`. Проверено запросом от имени YandexBot по `/`, `/news`, `/catalog/entrance-doors`.

Отсюда прямые ошибки в Вебмастере на всех 5 доменах:
- **SOFT_404** — робот считает страницы пустыми;
- дубли: 23 URL с идентичными мета-тегами → в индекс берётся одна;
- `canonical="/"` на каждой странице прямо говорит Яндексу «это всё главная».

Дополнительно:
- **NO_METRIKA_COUNTER_BINDING** — на всех 5: счётчик Метрики не привязан к сайту в Вебмастере;
- **NOT_IN_SPRAV + NO_REGIONS** — на .moscow, .store, .su, .online (на .pro уже ушло — значит способ рабочий);
- на 4 доменах в индексе висят случайные карточки фурнитуры, а не категории и статьи.

## План работ

### Этап 1. Пререндер статики (критично, без этого остальное не даст эффекта)
1. Подключить сборку пререндера: генерировать реальные HTML-файлы для всех статических маршрутов — главная, все категории каталога, страницы салонов, `/news` и каждая статья, контакты, бренд.
2. В каждый HTML вшивать свои `title`, `description`, `canonical` на полный URL домена, OG-теги и JSON-LD.
3. Ограничение по количеству файлов: только статические маршруты + статьи (около 25–40 на домен), карточки товаров пока остаются на клиентском рендере.
4. Настроить nginx: отдавать пререндеренный файл, если он есть, иначе `index.html`.
5. Проверить curl-ом от YandexBot, что у 5 разных URL разные title/canonical.

### Этап 2. Товарные карточки
6. Пререндер топ-товаров (до 200 на домен) с уникальными мета и JSON-LD `Product` + `Offer`.
7. Для остальных — оставить в sitemap, добавятся позже.

### Этап 3. Вебмастер и Метрика
8. Привязать счётчик Метрики к каждому хосту в Вебмастере (снимет NO_METRIKA_COUNTER_BINDING).
9. Досдать регионы и карточки Справочника на .moscow, .store, .su, .online — по схеме, которая сработала на .pro.
10. После пререндера — переобход всех URL через API (Recrawl + IndexNow).

### Этап 4. Семантика под коммерческие запросы
11. Сейчас трафик только брендовый. Собрать по каждому салону кластеры «входные двери <район>», «межкомнатные двери купить <район>», «двери с терморазрывом» и т.д.
12. Переписать тексты категорий и салонов под эти кластеры (сейчас категории вообще без текста в HTML).
13. Новая подкатегория «Термо» — отдельная посадочная страница с описанием.

### Этап 5. Контроль
14. Через 2 недели после выката: снять по API страницы в поиске, показы, клики по каждому домену и сравнить с текущей таблицей.

## Технически

- Пререндер: `vite-plugin-prerender` либо собственный скрипт на Playwright после `vite build` (Playwright уже есть в проекте).
- Источник маршрутов: `scripts/generate-sitemap.ts` (уже знает все статические роуты и статьи) — переиспользуем список.
- Мета-теги: `src/lib/seo.ts` и `useDocumentMeta.ts` уже формируют правильные значения на клиенте — пререндер их зафиксирует в HTML.
- Деплой: тот же `bun run build` + rsync, дополнительный шаг только внутри build-скрипта.
